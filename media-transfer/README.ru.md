# Перенос изображений TZ Portfolio — компонент 1.0.9

Версия 1.0.9 исправляет ложное срабатывание на случайные PHP-маркеры в бинарных данных, добавляет окно ошибки файла с отменой и пропуском и сохраняемый отчёт с полными путями. [Описание и проверки](../patches/media-transfer-file-errors-1.0.9.md). Защита путей и прав доступа сохранена. Манифест регистрирует сервер обновлений для штатной проверки совместимости Joomla 6.x.


В окне совпадения изображения или подписи кнопка «Отменить» останавливает всю текущую операцию и закрывает окно после подтверждения остановки сервером. Уже выполненные изменения сохраняются; их можно отдельно откатить.

Над списком материалов доступны кнопки «Выбрать всё» и «Снять всё». Они действуют на доступные материалы текущего источника; строки с ошибками не выбираются.

Административный компонент Joomla для **TZ Portfolio 4.1 и новее**.
Устанавливается и используется через браузер; терминал сервера не нужен.
Копирует изображения и подписи между дополнениями **внутри того же материала**.
Новые материалы не создаёт. Меню, категории и тексты материалов не переносит.

Для согласованного хранения новых копий в `images/com_tz_portfolio` установите **Gallery 2.1.6+** и **Flipbook 1.0.19+**. Чтение поддерживает также `images/tz_portfolio` и `images/tz_portfolio_plus`.

Для автоматического включения Content Gallery требуется дополнение **Gallery 2.1.5+** с пунктом «Галерея» в типах медиа.

## Ошибка отдельного файла

Перед копированием проверяются тип изображения, имя и путь. Найденный PHP-маркер
анализируется штатным Tokenizer без исполнения кода: одно совпадение `<?=` в
бинарных данных больше не блокирует корректное изображение. Для PNG дополнительно
проверяются структура, CRC блоков, полный zlib-поток и размеры строк, включая Adam7.
Проверка не является антивирусом и не гарантирует обнаружение любого вредоносного файла.

При ошибке файла операция приостанавливается и показывает полный путь и причину:

- **Отменить** — остановить операцию и закрыть окно. Уже выполненные изменения
  остаются; их можно отдельно откатить.
- **Пропустить файл** — оставить этот исходник и его подпись и продолжить.
- **Пропустить все** — пропустить текущий файл и последующие файлы с ошибками
  только в этой операции. Корректные файлы продолжают обрабатываться. Это не
  разрешение копировать подозрительные файлы.

Перед пропуском отменяются незавершённые записи текущего файла. При невозможности
восстановления, ошибке базы, изменении материала или прав доступа операция
останавливается без возможности обхода этой ошибки кнопкой пропуска.

Отчёт показывает общее количество пропусков, полные исходные пути и причины.
Он сохраняется в журнале операции, доступен после перезагрузки страницы, при
копировании и перемещении. В него также входят явные пропуски при совпадении
файлов. Для старых операций, созданных до 1.0.9, пути восстановить из журнала нельзя.

## Установка

1. В Joomla откройте **Система → Установка расширений → Загрузить файл пакета**.
2. Загрузите **`com_tz_media_transfer_v1.0.9.zip`**. Это компонент Joomla,
   его не нужно устанавливать в менеджере дополнений самого Portfolio.
3. Откройте **Компоненты → Перенос изображений TZ Portfolio**.

Вход доступен пользователям с правом управления компонентом. Для выбранных
материалов нужны права `core.edit` TZ Portfolio, для перемещения/отката также
`core.delete`. У суперадминистратора они есть. Права компонента регулируются
стандартной кнопкой «Настройки»/«Параметры» Joomla.

## Дополнения

Полностью проверен обмен в обоих направлениях между:

- **Flipbook Gallery** — формат присланного флипбука 1.0.14–1.0.19;
- **Content Gallery** — формат Gallery 2.1.x для Portfolio 4.1.

Добавлен источник **Грид галерея — Grid Gallery**, включая присланный формат
Grid Gallery 1.0.13 для Portfolio+ 2.7.3: `media.grid_gallery` с массивами
`data`, `title`, `featured`. После установки Portfolio 4.1.2 компонент читает
перенесённые данные материала напрямую, даже если нет современного провайдера
Grid Gallery. Старый PHP-код дополнения при этом не запускается.

Поддержаны копирование и перемещение Grid → Content Gallery и Grid → Flipbook,
порядок фотографий/подписей, миниатюры, разрешение совпадений и полный откат.
Исходники ищутся по каждому файлу в `images/com_tz_portfolio/grid_gallery/ID`,
`images/tz_portfolio/grid_gallery/ID`, `images/tz_portfolio_plus/grid_gallery/ID`.
Без совместимого дополнения Grid для 4.x он доступен только в списке «Откуда»;
в списке «Куда» остаются совместимые установленные дополнения.
Папку старого Portfolio+ и оригиналы сохранять до проверки новых копий.

**Произвольное неизвестное дополнение не становится совместимым автоматически.**
Каждому формату нужен адаптер. Схемы перечислены в
`admin/src/Service/Adapters.php`; для нового типа сначала проверяется формат
его данных и каталогов, затем добавляется и тестируется адаптер.

## Работа

При открытии загружается только список материалов: итоговые строки пусты, в шести
ячейках каждого материала стоят прочерки. Поиск файлов выполняется только кнопкой
«Найти изображения». В таблице три раздела:
«Флипбук», «Галерея», «Грид галерея», каждый с колонками «Изображения» и «Подписи».
Считаются существующие читаемые оригиналы, связанные с материалом; подпись
учитывается только у найденного изображения. Отсутствующие файлы и их подписи
в счётчики не входят. Каждое повторное нажатие заново проверяет файлы на диске.
Материалы в корзине исключаются. Неопубликованные материалы доступны при наличии
прав редактирования. При частичном наличии файлов переносятся только существующие,
а старые записи об отсутствующих файлах в источнике не удаляются. Повреждённые
структуры данных не обрабатываются.

1. Выберите **«Откуда»** и **«Куда»**, затем нажмите **«Найти изображения»**.
2. Отметьте нужные материалы или оставьте все исправные.
3. Выберите **«Копировать»** или **«Переместить»**.
4. При необходимости включите **переключение основного вывода на назначение**.
   Это переключит тип медиа (для Content Gallery 2.1.5+ — «Галерея») и параметр показа.
   При копировании флажок по умолчанию выключен, при перемещении включается.
   Дополнение назначения должно быть включено в Portfolio, чтобы переключить показ.
   Без флажка настройки не меняются: контентная галерея может показывать копии
   согласно существующему макету. Другие блоки макета не отключаются.
   Отступы, ширина и тип галереи не переопределяются.
5. Нажмите **«Начать копирование» / «Начать перемещение»**.

При копировании исходные данные сохраняются. При перемещении источник очищается
**только для успешно обработанных изображений** после проверки копии и записи
назначения. Пропущенные файлы остаются в источнике.

Отслеживаются и актуальные, и старые каталоги изображений, которые продолжают
читать дополнения Portfolio 4.1. Копируются оригиналы и относящиеся к ним файлы
из `resize`. Порядок новых добавлений соответствует источнику; существующие
изображения назначения не переставляются. Выбранное изображение назначения
сохраняется, если оно остаётся в списке. После окончания очищается кеш Portfolio
и страниц Joomla. Кеш CDN/внешних прокси, если он есть, регулируется отдельно.

## Совпадения изображений

Совпадения определяются **по имени и по SHA-256 содержимого**, в пределах одного
материала и дополнения назначения. Поэтому найдётся и та же фотография под другим
именем. Диалог показывает обе фотографии, имена, размеры, даты и подписи.

- **Заменить** — использовать позицию/имя существующего изображения назначения.
- **Оставить** — для одинакового содержимого использовать существующий файл и
  отдельно проверить подпись. Если содержимое отличается, исходное изображение
  пропускается целиком и при перемещении остаётся в источнике.
- **Переименовать** — добавить отдельную копию с именем вида `имя__copy_1.jpg`.

Если подписи нет в назначении, она заполняется автоматически. Если подписи
совпадают, повторный вопрос не нужен. Пустая подпись источника не стирает
существующий текст назначения. При разных непустых подписях доступны:

- заменить подпись текстом источника;
- оставить подпись назначения;
- **создать отдельную копию фотографии со второй подписью**.

Тексты не склеиваются. Последний вариант сохраняет существующее изображение с его
подписью и добавляет исходное под свободным именем с исходной подписью.

Флажок **«Применить ко всем»** действует только внутри текущей операции,
**отдельно для изображений и подписей**. Без флажка решение разовое.

## Прогресс, продолжение, откат

Изображения обрабатываются небольшими шагами, а не одним долгим запросом.
Прогресс и результат каждого изображения видны на экране. При закрытии страницы
обработка останавливается; откройте запись в журнале и нажмите «Продолжить».
Ожидающий решения конфликт также сохраняется. «Решить позже» не удаляет запрос.
«Остановить» прекращает следующие шаги; уже выполненные изменения остаются
видны в журнале и доступны для отката.

Перед заменой и удалением сохраняются резервные копии. Каждая копия проверяется
по контрольной сумме; метаданные записываются транзакцией InnoDB. Прерванная
подготовленная запись восстанавливается при следующем обращении к операции.
Потоковое копирование не загружает изображение целиком в память PHP.

**«Откатить операцию»** восстанавливает данные и файлы в обратном порядке.
Если после переноса изменились данные дополнений/настройки показа материала
или затронутые файлы, откат останавливается, чтобы не перезаписать новые правки.
После проверки и устранения конфликта откат можно повторить.

Резервные копии занимают место на сервере. Когда результат проверен и откат
больше не нужен, нажмите **«Удалить журнал»**: это удалит журнал и его резервные
копии, но **не фотографии в дополнениях**. Резервные файлы хранятся в служебном каталоге в PHP-контейнерах, которые при
веб-запросе возвращают 404 без содержимого; Apache дополнительно закрыт через
`.htaccess`. Изображение внутри контейнера читается только кодом компонента.
Дополнительная настройка веб-сервера или работа в терминале для этого не нужна.

Удаление компонента Joomla удаляет его журнал и резервные копии, но не готовые
фотографии/записи в Portfolio. Перед удалением завершите или откатите нужные
операции. Служебные таблицы компонента отделены от таблиц Portfolio.

## Проверено

На Joomla **5.4.10 / PHP 8.4.27 / Portfolio 4.1.2**, через настоящий установщик,
авторизованный API и интерфейс админки:

- оба направления, копирование/перемещение и переключение показа;
- совпадение имени с разными файлами, совпадение содержимого с разными именами,
  замена, оставление, явное переименование и применение ко всем;
- отдельные фотографии для двух подписей, пустые подписи, Unicode и безопасный
  вывод HTML-текста подписи без его исполнения;
- оригиналы и миниатюры, сохранность корзины, отсутствие/недоступность файла;
- продолжение после обновления страницы, остановка, журнал и удаление журнала;
- полный откат с точным сравнением данных и контрольных сумм;
- восстановление после прерванного запроса, отказ записи, защита последующих
  ручных правок, CSRF и недоступность чужих операций другому администратору.

Тесты: `tests/media-transfer/`. Тестовые данные создаются только на изолированном
стенде. База сайта, пароли и фотографии пользователя в пакет не включаются.

Базовый компонент прошёл полный набор проверок на Joomla **6.2.0 / PHP 8.4.27 / Portfolio 4.1.2** с отключённым плагином обратной совместимости Joomla 6. [Отчёт для версии 1.0.5 и воспроизведение](../patches/media-transfer-joomla62.md). Версия 1.0.9 проверена на Joomla 5.4.10 и 6.2.0; результаты перечислены в её отчёте.
