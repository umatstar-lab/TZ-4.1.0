# TZ Media Transfer 1.0.10 — миграция меню

Portfolio 4.1.2 продолжает использовать таблицы `#__tz_portfolio_plus_content`
и `#__tz_portfolio_plus_categories`. Старые ID сохранены. Меню Joomla при этом
может оставаться привязанным к отключённому `com_tz_portfolio_plus`; старые поля
редактора вызывают ошибку `COM_TZ_PORTFOLIO_PLUS_ADMIN_PATH`.

Новый раздел отдельно сканирует все меню сайта по option в ссылке или старому
component_id. Старый PHP-код компонента не подключается. Таблица показывает меню,
пункт, штатный тип, найденное назначение и причину запрета. Восемь сочетаний типов/
макетов сверены с поставками Portfolio+ 2.7.3 и Portfolio 4.1.2: article/default,
categories/default, categories/grid, portfolio/default, date/default,
search/default, myarticles/default, form/edit.

Соответствия проверяются по общим ID и существованию материала/категории вне
корзины. Проверяются фильтры категорий для portfolio/date, родитель поиска и
категория создания. Новое назначение отображается с названием и ID. Неизвестные
макеты, неоднозначные ссылки, внешние URL и отсутствующие назначения не меняются.
Неподдерживаемый пункт остаётся виден с причиной. Меню админки исключены.

Выбор галочками и кнопки выбора всех/снятия всех действуют только на подтверждённые
пункты. Меняются исключительно `link` (option) и `component_id`. Остальные query
параметры, фрагмент, идентификаторы, параметры/фильтры, публикация, язык, доступ,
SEO-путь, дерево, домашний пункт, модули и языковые ассоциации сохраняются.
Снятый с публикации пункт не публикуется автоматически.

## Защита записи и отката

API требует POST, CSRF, core.manage компонента и com_menus. Запись/откат проверяют
core.edit компонента меню и соответствующего меню. Списки ограничены 500 пунктами,
ID строго целые; SQL-значения экранируются. Ссылка назначения не принимается от
клиента. Сервер вычисляет её из проверенного маршрута и нового extension_id.
Результат поиска содержит HMAC состояния пункта и вычисленного назначения.
Перед записью проверяются права, блокировка, назначения и HMAC; подменённый,
повторный или устаревший выбор не применяется.

Группа выполняется под advisory lock и транзакцией с блокировкой строк. Журнал
с исходными и конечными строками пишется в ту же транзакцию. Откат доступен
владельцу журнала, повторно проверяет права и изменения. При настоящей ручной
правке отменяется вся группа отката. Служебный checkout не считается изменением
данных, но открытый редактор нужно закрыть. После записи очищаются кеши меню,
модулей, компонентов и страниц. Вывод таблицы через textContent.

Новая таблица `#__tz_media_transfer_menus` создаётся установкой/обновлением SQL
1.0.10; старые журналы и перенос изображений не меняются.

## Проверки

Изолированные Joomla 5.4.10 и Joomla 6.2.0, PHP 8.4.27, Portfolio 4.1.2;
на Joomla 6 плагин совместимости отключён. Установка поверх 1.0.9 штатным
установщиком. Тест `tests/media-transfer/menus.cjs`:

- два меню, вложенный пункт, все восемь типов/макетов;
- известные и отсутствующие назначения, корзина, неизвестный тип, внешняя ссылка;
- поиск без записи, выбор только одного пункта и всей группы;
- точное сохранение остальных полей, отключённой публикации, алиаса-ссылки,
  произвольного query-параметра и фрагмента;
- CSRF, подменённый HMAC, повторные ID, изменение после поиска и повторный запрос;
- запрет отката чужой операции и отказ перезаписывать ручные правки;
- точный откат по данным, безопасный HTML-вывод названий;
- открытие перенесённого пункта в штатном редакторе без старой ошибки;
- публичный маршрут меню действительно выводит опубликованный материал.

Дополнительно повторены тесты переноса изображений и обработки файловых ошибок.
В установщике только код и ресурсы компонента: без фикстур, журналов и данных сайта.
