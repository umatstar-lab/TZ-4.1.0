# Gallery 2.1.4: самостоятельная адаптивная раскладка

Исправляет приложенный `gallery_content_addon_v2.1.3_tzportfolio_4.1_article_context_fix.zip`.
Установочный архив: `gallery_content_addon_v2.1.4_tzportfolio_4.1_layout_fix.zip` в корне репозитория.
Это отдельное дополнение Gallery, а не обновление всего компонента TZ Portfolio.

Установка: менеджер дополнений TZ Portfolio → Загрузить → выбрать ZIP версии 2.1.4. Для вида с фотографиями разной высоты и подписями под ними используйте тип `Masonry` и положение подписи `Под изображением`. Число колонок зависит от ширины блока и настройки ширины фотографии (по умолчанию 400 px): на широком блоке получаются четыре колонки, на телефоне одна.

Причины сбоя в 2.1.3:

- Шаблон декодировал `gallery_content` из JSON, но `hasImages()` не делал этого. В таком случае фотографии выводились, а подключение ресурсов пропускалось. На исходном пакете это воспроизведено изолированным PHP-тестом.
- Masonry требовал `uk-grid`, но UIkit не подключался самим дополнением. Без него даже при наличии CSS не было самостоятельной многоколоночной раскладки.
- Скрытие служебного имени файла полагалось на внешние стили `visually-hidden`.

Изменения: единая обработка изображений из JSON/массива/объекта; нормализация массива или JSON всей галереи; самостоятельная раскладка через CSS columns без UIkit; подписи под фотографиями; ограничение изображений шириной колонки; скрытие служебного имени файла; абсолютные адреса ресурсов и версия 2.1.4 для обновления CSS/JS в браузере. Добавлено получение документа через фабрику Joomla, когда приложение ещё не назначило его. Галерея не включает фотографии пользователя в ZIP и не переносит данные.

Проверка итогового устанавливаемого ZIP: PHP-синтаксис, CRC архива, применимость `gallery-layout.patch`, девять PHP-страниц и 11 браузерных сценариев. Проверены пять форматов данных, четыре колонки при ширине 1800 px без UIkit, подписи под изображениями, открытие/закрытие Fancybox с украинской подписью, одна колонка при 390 px без горизонтальной прокрутки, grid/horizontal masonry/carousel, некорректные данные и отсутствие ошибок JavaScript. Исходный пакет ожидаемо не проходит проверку регистрации CSS при JSON-данных.

Тест использует настоящий класс представления, шаблон, CSS и JavaScript дополнения, с изолированными объектами Joomla для модели и регистрации ресурсов. Это проверка на тестовых данных, не на внешнем сайте пользователя. Заголовок и меню сайта из примера относятся к его шаблону Joomla и данным ZIP не изменяются.

В подготовленной среде с запущенным `tz-dev-web-1`:

1. `python3 tests/gallery/prepare.py`
2. `python3 -m http.server 8765 --bind 127.0.0.1 --directory /workspace/gallery-fix/preview`
3. `node tests/gallery/browser.cjs`

Docker и локальный HTTP-сервер могут требовать разрешённого выхода из песочницы. Тесты не запрашивают внешние сайты и не используют лицензионный ключ. `gallery-layout.patch` применяется к распакованному исходному дополнению командой `patch -p1`.
