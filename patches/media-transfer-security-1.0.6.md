# Проверка безопасности и обновление 1.0.6

Область: компонент `com_tz_media_transfer`, его API, обработка файлов, журнал,
резервные копии, откат и метаданные обновлений. Проверка исходников и негативные
тесты выполнены на локальных Joomla 5.4.10 и 6.2.0 / PHP 8.4.27 / Portfolio 4.1.2.
Рабочий сайт пользователя и сторонние дополнения не сканировались и не изменялись.

## Найденное и исправленное

### Проверка файлов

В 1.0.5 расширение `.jpg` само по себе разрешало скопировать файл с текстом PHP,
а имя `shell.php.jpg` проходило фильтр. Это воспроизведено на искусственных файлах
в отдельном временном каталоге, без исполнения их содержимого.

Это **не установленная анонимная загрузка веб-шелла**: компонент не имеет API
загрузки файлов, требуется доступ к компоненту и наличие подменённого файла в
известной галерее. Возможность исполнения зависела бы также от настроек веб-сервера.
Тем не менее, инструмент переноса не должен распространять такие файлы.

В 1.0.6:

- Исполняемые и двойные расширения PHP/PHTML/PHAR и другие скриптовые расширения
  отклоняются, включая варианты с разным регистром, `;`, пробелом и `%00` после PHP.
- Содержимое сверяется с типом изображения и расширением: JPEG, PNG, GIF, WebP,
  AVIF, BMP, TIFF. HTML/SVG и текст PHP под именем `.jpg` не копируются.
- Добавлена потоковая проверка PHP-вставок `<?php` и `<?=`, в том числе на границе
  блоков чтения. Обычная XMP-инструкция `<?xpacket` не отбрасывается.
- Перед началом и перед обработкой проверяются исходные изображения. Готовый
  временный файл повторно проверяется перед заменой назначения; это действует
  также при восстановлении из старой резервной копии.
- При отказе проверки готовый файл назначения не заменяется, исходник сохраняется.

### Пути и символические ссылки

1.0.5 отклоняла ссылки за пределы сайта, но допускала промежуточную ссылку на другую
папку внутри сайта. Для создания ссылки атакующему потребовался бы отдельный доступ
к файловой системе; обычный запрос к API не создаёт ссылок.

Теперь разрешены только известные каталоги изображений/миниатюр и защищённое
хранилище журнала. Любая символическая ссылка в любом сегменте пути отклоняется.
Пути повторно проверяются перед открытием и окончательной заменой файлов.
Нельзя указать `configuration.php`, произвольный файл сайта, абсолютный путь,
`php://`, HTTP-адрес или выход через `..`.

### Права после начала операции

Ранее автоматическое восстановление `prepared` и очистка после перемещения могли
срабатывать перед повторной проверкой прав на материалы. Владелец прежней операции,
сохранивший доступ к компоненту, мог вызвать такую обработку после отзыва права
редактирования материала.

Теперь права на материалы проверяются **до** восстановления/удаления файлов.
Негативный тест создаёт незавершённую запись, отзывает права, вызывает `status`,
`step`, `undo`, `undoStep`, `resolve` и проверяет отсутствие изменений файлов.
Остановить собственную операцию можно и после отзыва прав; удалить журнал с ещё
не восстановленной записью `prepared` нельзя. После возврата прав восстановление
проходит штатно.

### Запросы и резервные копии

Добавлены строгие типы полей запроса и ID, ограничение тела JSON 256 КиБ и глубины 32.
Доступ к компоненту проверяется и в контроллере, и в сервисе. Временные файлы создаются
с ограниченными правами, резервные копии остаются с правами `0600`; защитный PHP-префикс
завершает выполнение через `exit`/`__halt_compiler` до данных резервной копии.

## Дополнительные проверки

| Сценарий | Результат |
| --- | --- |
| SQL-инъекция в источник, ID материала и номер операции | Отклонена без изменений |
| Путь к конфигурации, обход папок, поток PHP, внешний URL | Отклонены |
| Запрос без входа, без CSRF, вызов через GET | Нет доступа/операция не выполняется |
| Чужая операция, даже при запросе другим суперадминистратором | Не раскрывается |
| Пользователь без `core.manage` компонента | Доступ отклонён |
| Неизвестные действия `upload`, `shell_exec` | Отклонены, файла/команды не создают |
| Слишком большой и слишком вложенный JSON | Отклонён |
| PHP-текст в JPEG, JPEG с PHP-хвостом, `<?=` | Не попадают в назначение |
| Промежуточные и конечные символические ссылки | Отклонены |
| Восстановление PHP-вставки из старой защищённой копии | Не создаёт публичный файл |
| Подпись с HTML/JavaScript | Выводится текстом, не исполняется |
| Прямой HTTP-доступ к резервным копиям | Закрыт на тестовом Apache |
| Копирование, перемещение, отмена, откат и прерывание записи | Регрессионные проверки проходят на Joomla 5.4 и 6.2 |

Тесты: `security-files.php`, `security-api.cjs`, `security-accounts.php`, а также
`inventory.cjs`, `engine.cjs`, `ui.cjs`, `cancel.cjs`, `failures.cjs`.
Тесты аккаунтов/прав запускать только на подготовленном изолированном стенде;
в конце они восстанавливают исходные правила и удаляют временную учётную запись.

## Совместимость, распознаваемая Joomla

В манифест добавлен сервер обновлений:
`https://raw.githubusercontent.com/umatstar-lab/TZ-4.1.0/main/updates/tz_media_transfer.xml`.
XML объявляет компонент для Joomla 5.4 и ветки 6.x, клиент `administrator`,
стабильную версию 1.0.6, ограничения PHP/БД и ZIP с SHA-256/SHA-512.
Проверка штатным `com_joomlaupdate` возвращает `state: 1` и `compatibleVersions: ["1.0.6"]`
для целей 5.4.10, 6.0.0 и 6.2.0. Для Joomla 7 совместимая версия не заявляется.
Метаданные 6.x не означают запуск тестов на каждой будущей версии Joomla.

После установки 1.0.6 сервер регистрируется в Joomla. Если проверка совместимости
уже запускалась ранее, очистить кеш обновлений Joomla и повторить её. Сайту нужен
исходящий HTTPS-доступ к GitHub и raw.githubusercontent.com.

## Границы результата

Проверка не является гарантией отсутствия любых уязвимостей или полноценным
антивирусным сканированием сайта. Не проверялись компрометация PHP/ОС/веб-сервера,
сторонние дополнения, владение аккаунтом суперадминистратора или запись атакующего
в файлы приложения/БД. При независимом доступе к файловой системе остаются общие
для переносимого PHP ограничения гонок между проверкой пути и операцией ОС.

Фильтр PHP-вставок намеренно консервативен: подозрительный файл не переносится;
исходник при этом не удаляется. Проверка формата не перекодирует фотографии и не
удаляет EXIF. Резервные файлы должны обрабатываться PHP либо быть закрыты правилами
веб-сервера; на Nginx защиту каталогов нельзя строить только на `.htaccess`.

Эта версия не ищет и не удаляет уже существующие веб-шеллы на рабочем сайте.
