# Исправления интерфейса TZ Portfolio 4.1.0

Исправленный установочный пакет: `../tz_portfolio_tz-portfolio.v4.1.0-fixed.zip`.
Исходный ZIP сохранён без изменений. Версия расширения остаётся 4.1.0.

Изменены только три файла:

- `setup/packages/admin/src/Helper/TZ_PortfolioHelper.php`: ACL-флаги хранятся с буквальными именами. Обычный Registry воспринимал точки как разделители: `core.edit` конфликтовал с `core.edit.state` и `core.edit.state.own`, из-за чего пропадали команды меню действий. Правила авторизации не изменены.
- `setup/packages/admin/layouts/form/field/modal/article.php`: обработчик одиночного выбора работает без jQuery, передаёт ID и название, отправляет событие change, закрывает Bootstrap 5 modal, включая выбор во время анимации открытия; поддерживает очистку и необязательную кнопку редактирования.
- `setup/packages/admin/tmpl/articles/modal.php`: поиск и фильтрация отправляются в `com_tz_portfolio`, а не в старый `com_tz_portfolio_plus`, с сохранением callback-функции.

`admin-ui.patch` показывает полный diff относительно исходного ZIP. Для применения к распакованному пакету из его корневого каталога: `patch -p1 < /path/to/admin-ui.patch`. Исправленный ZIP содержит те же изменения и устанавливается штатным установщиком Joomla. На локальном тестовом сайте исправления уже применены; внешние сайты и настройки облачной среды не изменялись.

Проверено: Joomla 5.4.1, PHP 8.4.27, Chromium. Команда `node tests/admin-ui.cjs` из корня репозитория использует подготовленный сайт `/workspace/tz-dev`, проверяет меню сохранения, создание статьи, меню действий и снятие с публикации, выбор типа меню «Один материал», поиск/выбор/очистку материала и отсутствие ошибок JavaScript. Тест создаёт собственную статью и после успешного выполнения перемещает её в корзину. Автоматический обучающий тур Joomla блокируется только в тестовом браузере, чтобы он не перенаправлял сценарий на главную панель.

Проверки синтаксиса трёх PHP-файлов и четыре базовые HTTP-проверки сайта пройдены. Joomla 6 в этой задаче не проверялась.

## Дополнение: лицензирование и каталог (Joomla 6)

`vendor-http.patch` применяется после `admin-ui.patch` и уже включён в обновлённый ZIP. Исправлены следующие места:

- Ответы HTTP читаются методами PSR-7 (`getStatusCode`, `getBody`, `getHeaderLine`). Это устраняет несовместимость клиента `Joomla\Http\HttpFactory` в общем загрузчике каталога с прежними свойствами `code`/`body`.
- Активация возвращает корректный ответ интерфейсу при сетевой ошибке, HTTP-отказе или неправильном JSON. Удалены `var_dump`/`die`, которые могли раскрывать служебные данные и ломать ответ. Ошибки не содержат ключ или URL с параметрами; HTTP-статус и имя сервера доступны для диагностики.
- Адрес файла обновлений переведён на HTTPS. Ключ в параметрах запроса каталога кодируется через `rawurlencode`, а некорректный XML обрабатывается без фатальной ошибки.
- Подтверждение лицензии, формат параметров сервиса и проверка TLS сохранены. Этот пакет не активирует Pro без подтверждения сервера.

Изолированный тест `tests/vendor-http.php` проверяет 22 сценария: PSR-ответ, контракт запроса, HTTP 401/403/500, неправильный JSON/HTML, сетевое исключение без утечки ключа, отказ лицензии, ответ каталога и сетевую ошибку каталога. В подготовленной среде: `docker cp tests/vendor-http.php tz-dev-web-1:/tmp/vendor-http.php` и `docker exec tz-dev-web-1 php /tmp/vendor-http.php`. Повторно пройдены браузерные регрессионные проверки и четыре HTTP-проверки Joomla 5.4.1/PHP 8.4.27.

Проверка после публикации сетевых настроек: доступ к производителю восстановлен. Реальный PHP-клиент Joomla получил HTTP 301 с `www.tzportfolio.com` на `tzportfolio.com`; при автоматическом следовании POST воспроизведены ошибка HTTP/2 и тайм-аут. Прямой POST на `https://tzportfolio.com` возвращает HTTP 200 и JSON. Встроенные адреса и адреса, полученные из XML, теперь нормализуются к каноническому HTTPS-хосту; переписывается только точный домен производителя. Автоматическое следование POST отключено, чтобы перенаправление не теряло тело запроса и токен. Проверка TLS сохранена; принудительное переключение HTTP-версии не применяется.

Ключ пользователя не получался и не использовался. Проверка API с пустым ключом ожидаемо возвращает отказ лицензии внутри корректного JSON, а не успешную активацию. Активация настоящей лицензии и скачивание платных пакетов по-прежнему требуют проверки на сайте пользователя.

### Уточнение HTTP 400

Если сервер отклоняет запрос, сообщение теперь содержит безопасный адрес операции (метод, хост, путь и только публичные поля маршрутизации) и текст поля `message` из JSON-ответа производителя. Токен и номер лицензии удаляются из текста; HTML страницы ошибки не выводится. Это диагностическое изменение, а не подтверждённое устранение HTTP 400 на сайте пользователя. Даже тело с `state=200` после HTTP 400 остаётся ошибкой и не активирует компонент. Параметры запроса сверены с текущим публичным кодом `templaza/tz_portfolio` и сохранены. Канонический хост определён по реальному HTTP Location.

### Исправление канонического хоста

Сборка включает исправленные константы активации/проверки лицензии как в установленном компоненте, так и в мастере установки. XML-манифест указывает канонический HTTPS-адрес. Общий загрузчик также исправляет старые ссылки с www, которые производитель продолжает выдавать в XML каталога. Предыдущие исправления интерфейса сохранены.

Живая проверка каталога дополнений: HTTP 200, `error.code=200`, `total=6`, список содержит 6 дополнений. Каталог расширений также возвращает HTTP 200 и JSON. Эти результаты получены без ключа пользователя; покупка и скачивание платных пакетов не выполнялись.
